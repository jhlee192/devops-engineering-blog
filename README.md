# DevOps Engineering Blog

운영 환경에서 마주친 문제를 재현 가능한 기술 기록으로 정리하는 개인 기술 블로그 원고 저장소입니다.

단순한 해결 명령어보다 **증상 → 조사 과정 → 원인 → 조치 → 검증**의 흐름과, 문제를 해결하는 과정에서 내린 기술적 판단을 기록합니다.

## 주요 주제

- **GitLab / GitLab Runner** — 파이프라인 실패, Merge 지연, 로그 보존
- **Kubernetes / Prometheus / Loki** — Pod 이력 추적, 스토리지 및 로그 운영
- **Docker / NGINX** — 컨테이너 운영, 레지스트리 접근 제어
- **Java / OpenJDK** — 인증서 및 CVE 대응

## 저장소 구조

```text
posts/            기술 기록
_templates/       트러블슈팅 및 구축 기록 템플릿
assets/images/    글에 사용하는 이미지
```

글은 Markdown으로 관리합니다. 각 글의 상태는 front matter의 `status` 값으로 구분합니다.

## 로컬에서 보기

현재 저장소는 Markdown 원고 중심입니다. GitHub에서는 각 Markdown 문서를 바로 읽을 수 있습니다. 별도의 정적 사이트 생성기를 도입하지 않아도 글을 확인할 수 있도록 구성했습니다.

## 기록 원칙

1. 실제로 확인한 내용과 추정한 내용을 구분합니다.
2. 재현 가능한 명령어와 검증 결과를 남깁니다.
3. 한 번의 사례를 모든 환경에 적용되는 일반 법칙처럼 단정하지 않습니다.
4. 공식 문서에 이미 설명된 내용은 출처 링크를 우선합니다.
5. 경험하지 않은 내용이나 확인하지 않은 성과를 추가하지 않습니다.

## 공개 범위 및 보안

이 저장소는 공개 가능한 범위로 정리한 개인 기술 기록입니다. 실제 업무 사례를 일반화하고 예시의 네트워크 주소와 식별 정보를 치환했습니다.

실제 환경에 적용하기 전에는 버전, 설정, 권한 및 영향 범위를 확인해야 합니다. 문서에 포함된 예시는 설명을 위한 값이며 운영 환경에 그대로 적용하면 안 됩니다.
